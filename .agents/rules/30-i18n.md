# 30 — i18n & RTL

- The existing bilingual mechanism is `LanguageContext` (`language: 'en' |
  'ar'`, `toggleLanguage()`, `t(key)`) plus the `{ en, ar }` object shape
  used throughout `products.json`. Do not introduce i18next/react-intl or
  any second i18n mechanism.
- Every new page/component consumes `useLanguage()` and renders both
  strings and direction correctly — set `dir="rtl"` at the appropriate
  wrapper when `language === 'ar'` if not already inherited from a parent.
- Prices, SKUs, and quantities are not translated, but their surrounding
  labels are; digits are not mirrored by RTL — only layout and text
  direction are.
- New translation keys are added to the single `translations` map in
  `LanguageContext.tsx`, not scattered across multiple files.
